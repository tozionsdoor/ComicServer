# ArcHive PC クライアント

別のPC（ノートPC・職場のPCなど）から自宅の ArcHive サーバーに繋いで、
ブラウザで書庫を開くための小さなランチャー。Python 標準ライブラリだけで動く。

Android アプリと同じ「LANで探す → 申請 → サーバー側で承認 → 端末別トークン」で認証する。
ブラウザに直接URLを打ち込むのと違い、**トークンを手で扱わなくてよい**のが主な目的。

## 使い方

```
pc_client\run_client.bat
```

- 初回:「LAN内のサーバーを探す」→ サーバーを選ぶ →「このサーバーに接続を申請」
  → サーバーPCの ArcHive サーバー画面 右下「端末」欄で承認（承認されると自動で繋がる）
- 2回目以降: 起動すると自動で接続 →「🌐 ブラウザで開く」

ショートカットに `--open` を付けると、繋がり次第ブラウザを開く。

```
pythonw.exe "...\pc_client\archive_client.py" --open
```

## できること

| 機能 | 説明 |
|---|---|
| LAN自動発見 | UDP 8770 にブロードキャスト。複数NIC（VirtualBox等）があっても全NICから投げる |
| 端末登録・承認待ち | サーバーに申請し、承認されるまで3秒おきにポーリング（最大180秒） |
| 接続先の自動選択 | LAN / IPv6 / グローバルIPv4 を**同時に**叩いて最初に応答した経路を使う |
| ブラウザで開く | ローカル中継経由。証明書の警告が出ず、URLにトークンも出ない |
| 複数サーバー | 保存した接続先をプルダウンで切り替え（自宅PC・NASなど） |
| 書庫を再スキャン | サーバーの `/api/scan` を叩く。本を足した後にPCの前まで行かなくて済む |
| トークンをコピー | 他のブラウザや端末に手入力したい時用 |
| 接続情報の自動更新 | 繋がるたびに IPv6 / グローバルIPv4 を取り直す（サーバーのIPv6は数時間で変わる） |

## 仕組み

```
ブラウザ ──HTTP──> 127.0.0.1:8766（このクライアント）──HTTPS(ピン留め)──> ArcHive サーバー
```

- **証明書ピンニング**: サーバーは自己署名TLSなので、LAN発見で受け取った
  SHA-256フィンガープリントと照合する（Flutter 版 `http_pinned_client.dart` と同じ）。
  一致しなければ接続しない。
- **ローカル中継**: ブラウザ→中継は素のHTTP（ループバックのみ）なので証明書の警告が出ない。
  中継→サーバーはピン留めTLSのままなので安全性は落ちない。
  中継は ArcHive クライアントが渡した鍵（クッキー）を持つリクエストしか通さないので、
  同じPCで開いている別のサイトから叩かれることはない。
- **読書履歴**: ブラウザビューワーの履歴は localStorage ＝ オリジン単位。
  中継ポートを固定しているのはこのため（ポートが変わると履歴が消える）。

## 設定ファイル

`%APPDATA%\ArcHiveClient\client_config.json`（`ARCHIVE_CLIENT_DIR` で変更可）

端末ID・接続先・トークンが入る。消すと再ペアリングからやり直しになる。

## 困ったとき

- **サーバーが見つからない**: 同じネットワークにいるか確認。初回起動時に Windows の
  ファイアウォールが許可を尋ねてきたら「プライベートネットワーク」を許可する。
  それでも駄目なら、サーバー画面に出ている `https://<IP>:<ポート>` を
  手で登録する経路は無い（ペアリングはLAN必須）ので、一度自宅LANで接続を作る。
- **外出先で繋がらない**: サーバーが IPv6 か UPnP でポートを開けている必要がある。
  どちらも無い環境向けの WebRTC P2P フォールバックは、このPCクライアントには未実装
  （Androidアプリのみ）。
- **「証明書が一致しません」**: サーバーを入れ直すと証明書も作り直されるため出る。
  接続先を削除して、もう一度ペアリングし直す。

## NAS版サーバーについて

NAS版（ReadyNAS）にも同じ手順で繋がる。承認する場所だけ違い、
サーバーGUIではなく **管理ページ `https://<NAS>:8765/admin` の「端末」** で承認する。

NASは古いOpenSSL（Debian 8）で動いているため TLS1.2 でも SHA-1 MAC の暗号しか喋らず、
今どきのOpenSSLは既定でそれを拒否する（ハンドシェイクが `UNEXPECTED_EOF_WHILE_READING`
で落ち、サーバーが死んでいるように見える）。そこで**TLSで落ちた相手にだけ**
セキュリティレベルを下げて繋ぎ直す。証明書のフィンガープリント照合はそのままなので、
「暗号は古いが、相手は確かに登録したサーバー」という状態は保たれる。
PCサーバーは従来どおり最新のTLSで繋ぐ（緩めるのは落ちた相手だけ・接続先ごとに記憶）。
